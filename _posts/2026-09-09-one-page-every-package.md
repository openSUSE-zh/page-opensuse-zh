在 openSUSE 论坛的帖子或 Reddit 评论区里，有一个问题反复出现：Leap 和 Tumbleweed 上的 X 到底是哪个版本？

直到最近，老实的回答往往还是“自己去查吧，一个软件包一个软件包地查”——除非真有人知道答案。

现在有了更好的答案。

[openSUSE 版本对比工具](https://opensuse.github.io/osdiff/)！！！
没错，[github.com/openSUSE/osdiff](https://github.com/openSUSE/osdiff) 这套工具会生成一份完整的、由机器构建的源码包版本对照，覆盖 Tumbleweed 与当前各 Leap 版本。

用便于查阅的格式列出源码包版本的想法，源自社区成员 Axel Braun 在一次[每周发布工程会议](https://calendar.opensuse.org/)上发起的讨论。
该站点会自动重新发布自己。没有猜测，没有轶闻，也没有过期半年的博客文章。只有数据。

该工具直接从 [download.opensuse.org](https://download.opensuse.org/) 拉取归档索引；涵盖开源软件（oss）与非 oss、x86_64 与 noarch，覆盖 Tumbleweed、Leap 16.1 和 Leap 16.0；然后逐一比较它找到的每个源码包的上游版本。最终结果是一张可排序、可筛选的单页表格，上面带有时间戳。

其规模值得驻足一看。最近一次运行覆盖了 17,532 个源码包：Tumbleweed 中有 17,143 个，Leap 16.1 中有 10,574 个，Leap 16.0 中有 10,551 个，其中 10,264 个同时存在于 Tumbleweed 和 Leap 16.1。每个软件包会归入以下五种状态之一：

| 状态 | 含义 |
| --- | --- |
| Older-in-Leap | Leap 提供的上游版本比 Tumbleweed 更旧 |
| Newer-in-Leap | Leap 实际上*领先*——比人们以为的更罕见，但确实存在 |
| Same | 两者上游版本完全相同 |
| Only-in-TW | 存在于 Tumbleweed，不存在于 Leap |
| Only-in-Leap | 存在于 Leap，不存在于 Tumbleweed |

页面还带有维护者信息，并且对自身结论的表述十分谨慎：只比较上游版本，不比较 RPM 发行版号。这一区别很重要，工具把它摆在明面上说清楚，而不是含糊其辞。

开放数据改变了这场对话。这里最有价值的不是那个 HTML 页面，而是页面底部可供下载的文件：`diff.json`、`diff.json.gz` 和 `diff.csv`。

这些开放数据把一个不错的网页变成了基础设施。任何人都可以拉取 JSON，而数据结构足够稳定，可以在其上构建应用。于是用例开始成倍增长。

* 正在 Leap 和 Tumbleweed 之间抉择的潜在用户。工作中需要特定工具链版本的人，十秒之内就能确认，而不必装上一遍才发现。

* 媒体、评测人和文档作者可以立刻找到深入相关话题所需的信息。这个页面能让记者即时获取信息，帮助他们判断某个 openSUSE 变体是否包含漏洞修复。发行版对比出了名地容易充斥过时或凭印象记下的版本号，而评测中写错的一个数字可能在搜索结果里流传多年。一份可引用、带时间戳、自动生成的来源，让“靠猜”不再有借口。如果你撰写 openSUSE 相关内容，现在终于有一个可以真正指向的脚注了。

* 像 DistroWatch 这样的聚合网站要追踪数十个发行版的软件包版本，为保持表格最新得付出大量手工或半手工劳动。把整个发行版的软件包集合以机器可读的格式导出并自动刷新，正是能让这类工作更省力、更准确的那种上游合作。DistroWatch 你怎么看？想要“什么里有什么”的对照表吗？

* 打包者和维护者能即时掌握情况。工具会在这些行上附上维护者姓名，让人知道该找谁。

* 正在寻找第一个任务的贡献者。加入发行版项目最难的环节之一，就是找到一件具体可做的事。一份经过筛选、列出落后的软件包及其维护者的清单，是一条真正友好的入门路径。

* 系统管理员和平台团队能快速确认开发所需的信息。在将一批机器从 Leap 16.0 迁移到 16.1 之前，或在评估某个工作负载能否从 Tumbleweed 迁到 Leap 时，实际的问题是哪些依赖会发生变化、变化有多大。16.0 与 16.1 的对照列直接回答了这个问题，而 CSV 可以不费吹灰之力地丢进电子表格或 diff 脚本里。

* 面向 openSUSE 的开发者将清楚用户会拥有哪些库版本——这就是兼容性矩阵。它还会告诉你，你自己的软件包是否存在于 Leap 中。

* 研究者和单纯好奇的人，都能在这些开放数据中找到不少乐趣。整个发行版的版本数据以固定周期公开发布，就是一个数据集。软件生态系统研究者和喜欢画图表的人，如今有了以前不存在的、以便捷形式呈现的原始素材。

让 Leap 的软件包版本与 Tumbleweed 的并排可见，是发布沟通方式上一次意义深远的转变。历史上，“下一个 Leap 里会有什么？”要等到周期末尾的发行说明来回答，或者由愿意深挖 OBS 的人拼凑出来。在开发中的发行版演进之际就公布其状态，意味着社区能看着发布逐步成形，而不是只拿到一份现成的总结。

这样的小工具很少得到应得的关注，但一张始终正确、始终最新、可自由下载的表格，会悄然为项目消除整整一类摩擦。
希望你喜欢它。
