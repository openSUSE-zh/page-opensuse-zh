## 更大的空间

openSUSE 在一段时间前转向了 `BLS`，使用 `systemd-boot` 和 `GRUB2-BLS` 这两款启动加载器。其中 GRUB2-BLS 如今基本上只是传统 `GRUB2` 的重新打包，因为主要补丁自 2.16 起就已合并进主线。

这一决定还要求 `ESP` 分区有更大的空间，因为现在所有快照的内核和 `initrd` 都存放在 `/boot/efi/$TOKEN` 中，其中 `$TOKEN` 取决于安装方式，可以是 `machine-id`、`opensuse-tumbleweed` 或 `opensuse-microos`。对于新安装来说这不是问题，因为安装程序（`YaST` 或 `Agama`）会建议创建一个大容量（1 GB）分区；而对于旧安装，迁移可能会相当麻烦，极端情况下分区甚至无法调整大小，此时建议保留旧的 `GRUB2-EFI` 启动加载器。

不过，如果我们决定使用 `systemd-boot`，还有一条后路：`XBOOTLDR`。

## 新分区

`XBOOTLDR` 是一个新分区，可以位于磁盘上的任何位置。`ESP` 在这方面存在一些限制，通常是系统的第一个分区。如果存在 `XBOOTLDR` 分区，`systemd-boot` 就会到其中查找菜单项以及内核 / `initrd`，从而让 `ESP` 不再承担这一职责。

该分区的文件系统也需要和 `ESP` 一样是 `FAT32`——这是 `UEFI` 的限制——并且在创建时需要指定特定的 `GPT` 标识符（`GUID`）。用 `fsdisk` 可以创建新分区并分配类型 `142` 或 `xbootldr`；这会把正确的 `GUID` 写入分区表，`systemd-boot` 便能识别它。

## 挂载点

由于这个新分区的出现，挂载点也需要相应调整。如前所述，openSUSE 摆放 `ESP` 的传统位置是 `/boot/efi`，但现在我们有了两个位置。UAPI 的建议是始终把启动项和内核放在 `/boot` 中，只有在启动加载器拥有独立分区时，才将该分区挂载到 `/efi`。现在正是这种情况，我们需要更新 `/etc/fstab`：

```
UUID=4165-E891 /efi  vfat utf8,dmask=0077,noexec,nodev,nosuid,nosymfollow 0 2
UUID=414C-528C /boot vfat utf8,dmask=0077,noexec,nodev,nosuid,nosymfollow 0 2
```

请修改 `UUID` 使其指向正确的设备。

如今 `sdbootutil` 能找到这两个分区，并根据是在更新启动加载器还是添加新条目，写入正确的位置。

现在我们可以迁移启动项和内核目录——它们原先都放在 `/boot/efi/loader` 路径下。手动将其移动到新分区即可，只需把 `loader/random-seed` 和 `loader/loader.conf` 留在原处，`loader/` 目录的其余内容都可以移走。
